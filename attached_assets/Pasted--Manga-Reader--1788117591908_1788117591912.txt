أريد منك تشخيص وإصلاح مشكلة حقيقية في تطبيق Manga Reader الخاص بي، وليس مجرد إخفاء رسالة الخطأ.

التطبيق يشبه Mihon، ولديه ميزة ترجمة صفحات المانجا/المانهوا باستخدام Google Gemini API عبر Gemini API Token.

بعد بعض التعديلات الأخيرة، عند الضغط على زر "Translate" تظهر نافذة:

"Page 2 Translation Failed"

والخطأ التقني الظاهر هو:

"IMAGE_DOWNLOAD_FAILED: Could not load the manga image (Failed to fetch)."

لقد أرفقت لك Screenshot يوضح المشكلة.

مهم جدًا:
لا تفترض أن المشكلة في Gemini API Key أو Token مباشرة. أريد منك تتبع دورة الترجمة كاملة ومعرفة أين تفشل عملية تحميل صورة الصفحة.

المطلوب منك:

1. افحص المشروع بالكامل وابحث عن كل الكود المتعلق بـ:
   - Translate / Translation
   - Gemini API
   - image loading
   - imageUrl / image URL
   - manga pages
   - fetch()
   - proxy
   - CORS
   - blob / Blob URL
   - base64
   - image download
   - OCR / image processing

2. تتبع العملية من لحظة ضغط المستخدم على زر Translate وحتى إرسال الصورة إلى Gemini.

3. حدد بالضبط أين يحدث:
   IMAGE_DOWNLOAD_FAILED

4. تحقق مما إذا كان رابط صورة الصفحة:
   - undefined أو null
   - غير صالح
   - URL نسبي بدل URL كامل
   - blob URL غير قابل للوصول من الـ backend
   - محمي بـ CORS
   - يحتاج Headers مثل Referer أو User-Agent
   - يحتاج Cookies
   - يتم تحميله من CDN يمنع server-side requests
   - يتم تمريره بشكل خاطئ بين frontend وbackend

5. تحقق أيضًا من التعديلات الأخيرة في المشروع وابحث عن regression تسبب في هذه المشكلة.

6. لا تقم بإزالة نظام معالجة الأخطاء فقط حتى تختفي النافذة.
   لا تستخدم fake/mock image ولا تتجاوز الخطأ بطريقة تخفي المشكلة.

7. أصلح المشكلة بالطريقة الصحيحة مع الحفاظ على البنية الحالية للتطبيق قدر الإمكان.

8. إذا كانت المشكلة بسبب CORS، لا تقترح فقط تعطيل CORS في المتصفح. استخدم الحل الصحيح، مثل proxy/server-side image fetching إذا كان مناسبًا لبنية المشروع.

9. إذا كانت المشكلة بسبب أن Gemini يحتاج إلى image bytes وليس URL مباشر، تأكد من أن التطبيق:
   - يحصل على الصورة فعليًا
   - يحولها إلى binary/base64 بطريقة صحيحة
   - يحدد MIME type الصحيح
   - ثم يرسلها إلى Gemini بالطريقة الصحيحة.

10. أضف logging مؤقتًا ومفيدًا حول عملية تحميل الصورة، مثل:
   - الصفحة التي تتم ترجمتها
   - image URL بعد حله
   - HTTP status
   - Content-Type
   - حجم الصورة
   - مكان فشل العملية

   لكن لا تقم بطباعة Gemini API Token أو أي Secrets أو API Keys في logs.

11. تعامل بشكل صحيح مع أخطاء الصور:
   - HTTP 403
   - HTTP 404
   - HTTP 429
   - CORS
   - timeout
   - invalid image
   - unsupported MIME type
   - network failure

12. تأكد من أن الإصلاح يعمل لجميع صفحات المانجا، وليس Page 2 فقط.

13. لا تغير تصميم التطبيق أو واجهته إلا إذا كان ذلك ضروريًا للإصلاح.

14. لا تستبدل Gemini بمزود AI آخر.

15. لا تطلب مني إعادة كتابة المشروع من الصفر.

بعد تحليل المشروع:
- اشرح لي السبب الجذري Root Cause باختصار.
- اذكر الملفات التي ستعدلها.
- نفذ الإصلاح بنفسك.
- شغّل اختبارات المشروع أو build/lint إن كانت متوفرة.
- اختبر تحديدًا مسار تحميل صورة المانجا ثم إرسالها إلى Gemini.
- تأكد من عدم وجود أخطاء TypeScript/JavaScript جديدة.
- تأكد أن الإصلاح لا يكشف API keys أو secrets للـ client.

ملاحظة مهمة:
التطبيق كان يعمل قبل بعض التعديلات الأخيرة، لذلك قارن الكود الحالي بالتغييرات الأخيرة إن كان Replit يوفر لك تاريخ التعديلات أو checkpoints، وحاول تحديد التغيير الذي تسبب في كسر image fetching.

لا تتوقف عند إعطائي اقتراحات نظرية. أريد منك فحص الكود الفعلي، تحديد السبب، ثم إصلاحه داخل المشروع.
